# 模块化控制面与 PostgreSQL 原子接受

Harniqo 采用模块化单体控制面，API/Worker 可以独立进程部署，七个业务 Module 共享 PostgreSQL 的显式事务。Run 接受、预算预留与 pg-boss job 登记经官方事务 Adapter 同事务提交，事件在提交后发布；队列重复交付只触发状态协调，不授权重复执行 Agent。

这保留跨授权、预算、执行状态的一致性，并控制首版运维成本。此阶段拆成多个业务微服务会把同一事务变成跨服务补偿；全量事件溯源又增加当前状态重建成本，所以不采用。未来独立扩容进程不要求先拆数据库，确有容量或团队 ownership 需要时再提取 Module。

代价是迁移与共享数据库需要统一纪律，业务写入只能通过所属 Module；事务与队列 Adapter 兼容性必须实测。架构已选定，真实验证和 Schema 冻结不因此视为通过。
