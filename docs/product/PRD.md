# Harniqo 首版产品规格

版本：1.0 · 日期：2026-10-29 · 对应任务：M0-01。

本文固定首版的使用者、权限、导航、用户流程和验收口径，供后续界面、契约及实现共同使用。它是需求规格，不表示以下功能已经开发、集成或上线。术语采用 [GLOSSARY](../../GLOSSARY.md)，技术实现遵循 [ARCHITECTURE](../architecture/ARCHITECTURE.md)，功能验收关联 [ACCEPTANCE](../planning/ACCEPTANCE.md)。

## 1. 产品目标与交付边界

Harniqo 让用户通过 macOS、Windows、Linux 客户端，在获准的云端执行环境部署或连接多个 Harness，持续对话、处理人工交互并取得文件，然后用相同任务比较不同运行配置。平台保存授权、配置、任务、原生身份、结果和费用来源；用户不需要在桌面安装全部 Harness。

首版同时交付团队私有部署与多租户 SaaS 配置，二者共享资源模型、权限、客户端与工作流程。私有部署允许使用客户自己的身份、存储、密钥与执行资源，外部模型和工具依赖必须声明；SaaS 的租户、执行身份和资源边界须通过独立验收，不能从已有 Harness 的多用户界面推导出已隔离。

| 首版必须交付 | 明确范围 |
| --- | --- |
| 三端工作台 | 多平台环境连接、登录、组织/项目切换、部署、会话、任务、产物、对比、评测与设置 |
| 团队与权限 | 组织/项目成员、固定角色、邀请/撤权、资源授权与操作审计；不开发自定义角色编辑器 |
| 运行管理 | 已有服务连接与平台托管分开；固定发行包/配置、能力准入、RuntimeInstance、健康、排空与升级/恢复 |
| 通用工作 | 文本与附件输入、原生连续会话、工具过程、审批/澄清、取消、断线重连、任务中心、安全预览与下载 |
| 配置 | 模型端点、Secret 引用、工具/skills/MCP、权限/记忆/资源/预算策略的版本化配置 |
| 正式接入 | 至少三种通过准入的 Harness；候选顺序按 M0 证据锁定；Octop 服务、Octop Harness 与外部委派分别给出状态 |
| 比较与评测 | 单任务并排比较、冻结候选与输入、任务集/Manifest、矩阵/重复、独立评分、统计、导出和重跑 |
| 生产交付 | 计量与配额、执行对账、诊断、数据保留、备份恢复、私有安装与 SaaS 配置、真实三端安装升级 |

首版执行环境限 Linux。Windows/macOS 专用 Runner、移动端、离线执行、同一会话多人同时输入、无损跨 Harness 状态迁移、自动挑选最优 Harness、插件交易市场和复杂工作流画布不进入首版。用户切换 Harness 时显式创建新的原生会话，选择传递任务、摘要和文件；不承诺隐藏上下文、工具状态或长期记忆自动迁移。

## 2. 使用者与部署责任

| 使用者 | 私有部署中的职责 | SaaS 中的职责 |
| --- | --- | --- |
| 平台运维人员 | 安装和维护本平台实例、身份/密钥/存储、Runner、备份与升级 | 维护公共控制面与执行池、容量、租户限额、故障对账与恢复 |
| 组织 Owner/Admin | 管组织和成员，将已获准执行目标分配给项目，管理组织预算/配置约束 | 管自己的组织；不能取得平台宿主或其他组织管理权限 |
| 项目 Maintainer | 配置部署和模型/工具权限、管理项目成员与运行版本、维护任务集/评分版本 | 同样限定在本组织项目内，使用平台分配的执行目标 |
| 项目 Operator | 发起对话、上传输入、运行对比/实验、处理自己的任务和读取结果 | 同样流程，受组织/项目资源与费用限额约束 |
| 项目 Approver | 检查具体动作和上下文，允许/拒绝待审批动作 | 同样流程，不因能审批就能改部署或取得长期密钥 |
| 项目 Viewer | 阅读获准项目的任务、过程、产物与报告 | 同样流程，不可启动执行、改变配置或批准动作 |

平台运维身份与组织角色分开。平台运维默认只看运行健康、资源和脱敏故障信息，不自动获得用户对话、业务文件或模型 Secret；内容排障通过有权限的项目成员选择导出的诊断材料进行。私有实例中同一个人可以同时承担运维和组织 Owner，但凭据与动作授权仍分开。

Runner 的登记/撤销与宿主授权由平台运维完成；组织管理员只能把已归属/授权给本组织的执行目标授予项目，不能借登记表单获得任意宿主权限。首版不要求 SaaS 租户拥有虚拟机管理凭据。

## 3. 资源可见性与固定权限

所有业务资源明确属于组织，项目资源另有项目归属。列表、搜索、流订阅、历史、文件、报告和导出使用同一授权范围。默认无成员关系即无访问；知道资源 ID、原生 session ID、对象路径或旧下载地址不授予权限。

首版会话、输入、产物和实验属于项目，在当前项目的获准读取成员之间共享；没有额外的“个人私密会话”开关。创建时在项目名称下显示这一可见范围，上传和发送前可确认当前项目。不同项目不因属于同一组织就默认共享业务内容，组织 Owner/Admin 的下述管理继承除外。

### 组织角色

| 动作 | Owner | Admin | Member |
| --- | --- | --- | --- |
| 查看本组织基本设置/本人角色 | 允许 | 允许 | 允许 |
| 创建项目、管理组织普通成员/邀请 | 允许 | 允许；不能变更 Owner/Admin | 不允许 |
| 授予/撤销组织 Admin、转让 Owner | 允许；必须保留至少一个有效 Owner | 不允许 | 不允许 |
| 管组织预算、分配获准执行目标 | 允许 | 允许 | 不允许 |
| 管组织级配置约束/凭据引用 | 允许 | 允许 | 不允许 |
| 访问本组织项目 | 继承各项目 Maintainer | 继承各项目 Maintainer | 仅按项目成员关系 |
| 归档/删除组织及其数据 | 允许，按保留/执行停止规则 | 不允许 | 不允许 |

加入组织不等于加入所有项目。组织邀请和项目邀请由获得相应权限的人发起，绑定组织/目标角色、有效期和被邀请身份；过期、已使用或已撤销邀请不能重放。不得通过自行注册、相同 email 后缀或客户端传入 role 提升权限。

### 项目角色

角色可叠加，权限为已授予固定角色的并集；Maintainer 包含 Operator、Approver 和 Viewer 的能力。项目角色只能授予该组织的有效成员，不能借项目管理升级组织角色。

| 动作 | Maintainer | Operator | Approver | Viewer |
| --- | --- | --- | --- | --- |
| 读项目会话/任务/日志、预览下载产物、读导出报告 | 允许 | 允许 | 允许 | 允许 |
| 看项目用量、预算剩余及费用精度 | 允许 | 允许 | 允许 | 允许 |
| 新会话、发送/上传、回复本人 Run 的澄清问题 | 允许 | 允许 | 不允许 | 不允许 |
| 使用已发布配置，创建对比、运行已发布任务集 | 允许 | 允许 | 不允许 | 不允许 |
| 取消本人提交的 Run/对比/实验 | 允许 | 允许 | 不允许 | 不允许 |
| 取消本项目其他成员的执行、接管澄清 | 允许，保留操作者与理由 | 不允许 | 不允许 | 不允许 |
| 批准/拒绝本项目待审批动作 | 允许 | 仅另有 Approver 角色时 | 允许 | 不允许 |
| 管部署、配置/Secret 引用、工具权限与版本 | 允许 | 不允许 | 不允许 | 不允许 |
| 发布任务集、Verifier 版本或项目预设 | 允许 | 不允许 | 不允许 | 不允许 |
| 管项目成员/角色、项目预算和保留策略 | 允许，不得超组织限额/约束 | 不允许 | 不允许 | 不允许 |
| 看长期密钥原值、取得宿主管理身份 | 不允许 | 不允许 | 不允许 | 不允许 |

有 Approver 能力的人可以响应自己提交的 Run 的审批；单人私有项目的 Owner 因继承 Maintainer 也可确认自己的动作。需要职责分离的团队通过只给操作人员 Operator、另给审批人员 Approver 来配置。审批权限不扩展工具、网络、预算或配置中已禁止的动作。

**撤权规则：**新命令、幂等重放、审批、下载/续传和新订阅重新检查当前权限；活动订阅/传输按验收基线的撤权时限关闭。首版移除成员阻止其后续操作，已接受 Run 继续归组织管理，不自动取消；Maintainer/组织管理员可明确请求停止并留痕，不以退出登录代替停止。已经下载到本机的副本不在平台可撤回范围内。

## 4. 导航与页面责任

全局顶栏始终展示当前平台环境、组织、项目和连接状态；切换上下文时先明确离开当前视图，再加载目标范围，不能短暂展示上个组织的数据。后台云任务不会因切换项目而取消。

```text
平台环境 / 登录 / 组织与项目选择
  └─ 当前项目
      ├─ 工作台：会话列表、连续对话、工具过程、审批/澄清、文件面板
      ├─ 任务中心：跨会话运行、等待处理、失败/未知、筛选搜索和通知
      ├─ 部署：Harness 目录、部署修订、能力、运行实例、健康与升级
      ├─ 配置：模型、Secret 引用、工具/skills/MCP、资源与权限配置修订
      ├─ 对比：单任务创建、并排执行、结果、人工选择和重跑
      ├─ 评测：任务集、实验预检/创建、Trial、评分与报告
      ├─ 用量：本项目预算、预留/实耗/待结算、精度与限制
      └─ 设置：成员、角色、项目策略、审计与诊断
组织管理：成员/邀请、项目、组织约束、预算与执行目标分配
平台运维：独立身份下的节点/资源/备份/升级与健康视图
```

每个入口具有加载、空数据、可用、无权限、连接失败及不兼容状态；空数据不能误写成“没有任务”，连接失败不能覆盖最后已知状态。无动作权限时不提供可执行按钮，API 仍独立拒绝。不可见资源按不可见处理；资源可见但缺操作权限时显示该动作所需角色。

## 5. 共用交互规则

| 规则 ID | 产品行为 |
| --- | --- |
| PR-01 | 创建执行前固定项目、配置修订、输入快照和策略；显示实际 Harness/Adapter/模型身份，不静默切模型或改成另一个代理组合 |
| PR-02 | 能力分为已验证支持、不支持、未知，并附版本/模式/限制；需要的能力不满足时阻止启动，并指出替代配置或管理员处理入口 |
| PR-03 | 一次提交具有稳定命令身份；超时/断线后先查询提交结果，再决定是否重试相同命令，不用第二次点击创建另一 Run |
| PR-04 | 已接受只表示平台持久受理；排队、执行、执行结束、业务成功与最终费用结算分别展示，不相互替代 |
| PR-05 | 同 Session 仅允许一个非终态 Run；再次输入保留为草稿，审批和澄清走对应交互入口。不同会话需要独立获准 Workspace，不能并行写同一工作区 |
| PR-06 | 关闭页面、退出客户端、客户端升级或网络断开不隐式停止云任务；取消使用明确动作和执行端确认 |
| PR-07 | 重试、新 Attempt、新会话、原生续接和配置更改分别命名；任何重新执行都有可追溯身份和累计用量，不覆盖旧证据 |
| PR-08 | 通知只提示项目、任务和待处理类别，不默认带业务正文、密钥或附件；系统通知被拒时任务中心仍可用 |

### Run 的用户可见状态

| 平台状态 | 用户文案/允许行为 |
| --- | --- |
| accepted | 已受理；可查询/取消，尚未开始调用 Agent |
| queued | 排队中；显示等待原因与资源/预算约束，不能编造开始时间 |
| provisioning | 正在准备执行环境；可取消，失败要给出资源/版本/连接原因 |
| running | 执行中；显示文字、工具和实际过程，可请求取消 |
| waiting_approval | 等待审批；显示动作、参数摘要、可审批身份和有效状态，不能自动允许 |
| waiting_input | 等待补充输入；显示原生问题与回答入口，迟到回答不作用于其他 Attempt |
| stopping | 正在停止；取消请求已受理，仍可能有在途费用，不显示已取消 |
| reconciling | 执行状态核对中；显示最后确认时间与原因，禁止一键重复写同一工作区 |
| succeeded | 执行结束；可看产物/继续会话；是否业务成功由客观评分或用户判断另列 |
| failed | 执行失败；保留已发生过程、费用和产物，按错误类别给可用恢复动作 |
| cancelled | 已取消；有实际停止证据，可看已产生结果，待结算费用仍显示 |

## 6. 流程 A：部署或连接 Harness

**操作者与入口：**项目 Maintainer，在“部署”创建；Operator/Viewer 只能读取部署并使用已发布可用配置。

**输入：**托管或外部连接模式、固定 Harness/Adapter 发行包、运行配置修订、已获准执行目标、模型端点及 Secret 引用、工作区/记忆/工具/审批策略、资源和预算上限。外部模式另填获准服务地址及该组织身份，禁止把共享管理员凭据视为不同用户已隔离。

**流程：**选择模式 → 展示发行包许可/版本/能力 → 填配置并保存草稿 → 预检权限、模型、Secret、能力与资源 → 确认发布配置并创建部署修订 → 托管模式准备资源、外部模式测试真实服务身份/连接 → 按健康与能力证据进入可用状态。

**输出：**Deployment ID、部署修订、实际版本/镜像、配置 hash、能力与健康结论、可使用范围；实际运行的 RuntimeInstance 另列所属 Workspace、执行状态和资源。配置草稿保存成功、TCP 连通和正式准入通过是三个不同结果。

| 异常/后续操作 | 必须行为 |
| --- | --- |
| 模型/Secret 无效或被撤销 | 显示对应配置引用与错误类别，不回显密钥；保留草稿，可更换后重新验证 |
| 必选能力未知/不支持 | 阻止该流程发布为可用；清楚列出缺项，不采用自动放行或降级成外链 |
| 资源不足、节点失联、启动超时 | 返回持久状态和诊断 ID；按原实例身份核对，不重复创建未确认实例；资源可清理/回收 |
| 外部地址指向内部管理网/越权服务 | 拒绝连接，不充当任意内网代理；不因用户为 Maintainer 绕过平台边界 |
| 暂停或升级 | 暂停接新任务/排空，保留活动会话；新版本是新修订，旧 Run 不被改写；数据不兼容时要求已验收的迁移/恢复路径 |
| 删除部署 | 先停止接新任务并核对活动实例；保留审计、历史与所需恢复记录，不能只删一行留下执行资源 |

**通过标准：**至少一个正式目标能从客户端完成真实部署并运行任务；正式支持集合至少三种；部署状态和实例状态可解释、不支持能力不会被当支持。关联 AC-05、AC-12、AC-13、AC-14、AC-15、AC-16、AC-24。

## 7. 流程 B：连续对话与任务执行

**操作者与入口：**Operator/Maintainer，在“工作台”创建或打开本项目会话。

**输入：**已发布配置、文本任务、获准附件快照、预算/资源限制；续聊另选该会话的原生身份。新会话在首版默认拥有独立 Workspace，上传/输入区显示项目共享范围。

**流程：**预检配置与能力 → 提交一次命令 → 展示持久 Run ID 与排队状态 → 持续显示文本、工具、原生关联和人工交互 → 执行结束后展示产物和费用状态 → 下一次输入在同一获准原生会话中继续。无活跃 Run 才允许发送下一条；需要分支或换 Harness 时明确创建新的原生身份。

**输出：**Session/NativeSession、Run/Attempt、配置与输入来源、持久过程、实际模型/工具/文件、终态与费用；用户能从任务中心回到该记录。

| 异常/用户动作 | 必须行为 |
| --- | --- |
| 提交超时、重复点击、客户端重开 | 使用相同命令查询/补取已受理结果；不隐式创建第二个 Run、预算预留或 Workspace |
| 退出/断网、游标过期 | 云任务按策略继续；重新授权后以快照和游标恢复；显示断网与最后已知状态，不写“已停止” |
| 模型限流/鉴权/工具/资源错误 | 分类展示发生阶段、重试边界和诊断入口；失败费用不被清零；不可安全重放的动作需显式新执行 |
| 请求取消 | 已派发执行先进入“正在停止”，确认实际停止后才“已取消”；未派发 Run 需确认没有有效执行指派后撤销，不能留下迟到启动；不能确认时“状态核对中”，不开放第二写者 |
| 原生续接/恢复不支持 | 保留历史供读取，明确提供新会话或允许的输入传递；不能把历史展示冒充恢复了原生上下文 |
| 更改模型/Harness/配置 | 对下一次执行创建/选择新配置；若需要新原生会话则明确展示，不回写既有 Run 的事实 |

**通过标准：**完成至少两轮有原生连续状态的真实任务，包含工具和文件；退出客户端后结果可恢复，重复提交不重复执行，取消与未知状态真实。关联 AC-04、AC-05、AC-06、AC-07、AC-08、AC-09、AC-29、AC-30。

## 8. 流程 C：审批与澄清

**操作者与入口：**Approver/Maintainer 在当前会话或任务中心处理审批；Run 提交者回复澄清，Maintainer 可接管并留痕。

**输入：**当前有效的交互 ID、所属 Run/Attempt/原生调用、工具名、目标与参数摘要、权限/策略、发起与失效状态；澄清显示需要用户决定的问题、答案结构和附件范围。原始敏感参数按策略遮蔽，不能省略影响决策的目标/操作含义。

**流程：**收到待处理事件 → 按项目与动作重新授权 → 展示具体内容 → 用户允许/拒绝或回答 → 服务端校验当前状态、内容、身份与有效期 → 显示已生效或已失效 → 回到 Run 的下一状态。响应确认前不乐观显示工具已执行。

**输出：**响应者、决定/答案、作用对象与内容摘要、时间、执行端接收结果和审计记录；等待状态与仍可处理的任务可在重启后恢复。

| 异常/竞态 | 必须行为 |
| --- | --- |
| 用户无审批权、被撤权、跨项目响应 | 拒绝并刷新可用动作，不将响应交给 Harness |
| 参数变化、TTL 过期、Run 停止、Attempt/代次变化 | 原交互失效；需要时生成新交互，不沿用旧批准 |
| 两人同时响应/重复点击 | 只一个有效决定生效，另一响应读到已处理结果；冲突可见且可审计 |
| 拒绝/超时 | 按已发布策略和原生能力拒绝/停止或保持等待，显示后续结果；不能默认为允许 |
| 需要审批却 Adapter 不支持 | 执行前拒绝启动该工作流，不能以“自动允许”填补能力 |

**通过标准：**允许、拒绝、过期、撤权和重放各有真实结果；拒绝实际阻止相应动作；已批准不扩大配置原本禁止的能力。需要阻断恶意代码的外部动作还须由拥有凭据的工具/出口控制执行，单个弹窗不构成该保证。关联 AC-03、AC-10、AC-14、AC-15。

## 9. 流程 D：输入与文件交付

**操作者与入口：**Operator/Maintainer 上传输入；所有项目读取角色在工作台/产物面板/报告查看获准产物。

**输入：**本地选定文件、声明类型/大小、目标项目及用途；可执行内容仅在获准隔离环境中处理。上传时创建冻结快照，原本地文件后续修改不会改变已经提交的输入。

**流程：**选择并校验 → 上传 → 校验完整性/实际对象 → 标记可用输入 → 绑定 Run/Manifest → 执行提交产物 → 校验后发布 ready → 安全预览或受控下载/另存。输入上传完成、执行完成和产物 ready 各有状态。

**输出：**文件对象与内容 hash、输入快照/产物 ID、来源 Run/Attempt/Trial、时间、类型/大小、可用/隔离/删除状态；报告中的文件可追溯到原执行。

| 异常/用户动作 | 必须行为 |
| --- | --- |
| 网络中断、大小/类型超限、hash 不符 | 保留明确上传状态与可恢复/重传动作；不发布损坏或未确认产物 |
| 对象成功但业务事务失败 | 用户看不到幽灵 ready 文件；后台对账可找回或回收孤儿 |
| 路径穿越、符号链接、恶意文件名/主动内容 | 拒绝越界；预览不能执行本机代码、导航到特权页面或窃取登录态 |
| 不支持预览的格式 | 显示格式与受控下载，不能伪装生成了可读预览；下载文件能通过对应格式/结构验收 |
| 下载中撤权/续传、已过保留期 | 新请求/Range 再授权；活动流按目标时限终止；已下载副本不能远程抹除 |

**通过标准：**输入冻结、来源和校验可查；恶意输入不能越界；产物真实可取且格式有效；UI 不把“生成了一个路径”当成已经交付。关联 AC-03、AC-11、AC-20、AC-26、AC-31。

## 10. 流程 E：单任务并排对比

**操作者与入口：**Operator/Maintainer，在“对比”创建；读取角色可看结果和人工选择记录。

**输入：**同一任务与输入快照、至少两个已发布候选、初始记忆/环境、权限、资源/并发/预算。正式验收覆盖至少三个正式集成；候选是完整运行配置，不只是 Harness 或模型名称。

**流程：**选择“尽量固定条件比较 Harness”或“比较完整配置组合” → 预检候选差异/模型兼容/计划消耗 → 固定快照并创建 → 每候选独立工作区执行 → 并排查看过程、产物和指标 → 记录用户选择与理由 → 可将选定配置保存为项目预设或重跑。

**输出：**Comparison ID、任务/输入来源、每候选的 Run/Attempt 与配置、文字/工具/产物、错误、时间/费用/人工干预、用户选择及适用任务范围。保存预设由 Maintainer 发布；Operator 可提交选择记录，不能擅改项目默认配置。

| 异常/差异 | 必须行为 |
| --- | --- |
| 实际模型无法固定、资源或能力不等价 | 创建前展示差异；不能静默换模型。选择改成明确的组合比较或移除不兼容项，并保留决定 |
| 一候选失败/取消/未知 | 只影响该候选；其余结果保留，缺失项显示原因，已产生费用累计 |
| 改变原预设、共享文件/记忆 | 既有对比快照不变，各候选写入和记忆隔离；不得用一候选的结果初始化另一候选 |
| 重跑或选择获胜者 | 创建新身份并关联来源，旧记录不覆盖；用户选择不是平台宣称全局最优 |

**通过标准：**三个正式集成能对同一真实任务独立运行，一个失败不会丢其余结果；过程、产物、差异、费用精度及选择均可追溯。关联 AC-05、AC-15、AC-16、AC-17、AC-22。

## 11. 流程 F：批量实验与报告

**操作者与入口：**Maintainer 发布任务集与 Verifier 版本；Operator/Maintainer 运行已发布任务集；读取角色浏览获准报告。

**输入：**固定任务集版本/输入 hash/许可与成功条件、候选配置、重复次数、资源/网络/记忆/审批策略、总预算及并发、评分版本/rubric。预检显示所有计划 Trial、兼容性、成本精度和需要人工处理的任务，不默认自动批准。

**流程：**导入/校验并发布任务集 → 选择候选/重复/策略 → 生成计划预览 → 固定 Manifest 并启动 → 每个 Trial 独立准入和执行 → 独立 Verifier 评分 → 汇总并钻取原始过程/文件/费用 → 导出清单和报告或创建新实验重跑。

**输出：**Experiment/Manifest、全部计划 Trial（含不兼容、取消、未知）、关联 Run 与全部 Attempt、Agent 结果、独立评分、报告和费用账本。一个 Trial 获准后关联一个逻辑 Run，重试增加 Attempt，不改变计划 Trial 数量；评分尝试与 Agent 尝试分开。

| 异常/统计情形 | 必须行为 |
| --- | --- |
| 不兼容、鉴权/限流/基础设施失败、取消/状态不明 | 每个计划项保留身份与原因，不静默删除来提高成功率；不得仅因租约过期启动第二写者 |
| 重试/评分器错误 | 保存首次与全部 Attempt、原因、累计费用/时间；评分器错误独立列示，不当成任务失败或自动通过 |
| 预算不足、并发/存储超限 | 未准入项排队或阻止，并显示具体约束；取消和失联先核对实际消耗再释放未消费预留 |
| 修改模型/数据/工具/记忆/评分版本 | 另建 Manifest/实验；不能覆盖运行中或既有实验的条件 |
| Judge 与客观结果冲突 | 客观失败保留；Judge 的 rubric/模型/输出和人审记录可查，不能覆盖失败 |
| 可靠性故障注入 | 单独标记实验用途与样本，不混入自然效果榜单；仍保留完整计划项与费用 |

**报告固定口径：**同时显示有效评分成功率、全部计划成功交付率和有效评分覆盖率，各自列分子/分母；列明首次/最终规则、人工干预、任务/基础设施/评分错误、样本数/波动、等待/启动/执行/评分耗时及 actual/estimated/unknown 费用。精确口径以 ACCEPTANCE 第 4 节为准，不将未知费用记为零。

**通过标准：**20 个任务 × 3 个候选 × 3 次重复产生 180 个计划 Trial，全部能对账并从报告回到原始证据；同 Manifest 可追溯重建输入与环境，不承诺随机模型逐字输出一致。关联 AC-18、AC-19、AC-20、AC-21、AC-22。

## 12. 用量、数据与运行支持的产品行为

用量页分别显示组织/项目限额、预留、已发生、待结算与可用余额；费用按模型/执行环境/存储/评分/重试拆分，并标明币种、价格来源和精度。直接 BYOK 或不透明端点只声明可观测的限制，不用“费用硬封顶”掩盖在途请求或外部结算误差。

历史、文件、原始轨迹和报告的保留策略在项目设置展示，组织约束优先。归档/删除前显示影响、活动执行与保留要求；仍在执行或状态不明的工作区不能直接物理删除。删除与备份保留范围需要明确说明，不宣称一次点击已从所有历史备份擦除。

诊断由有权限的用户主动生成、预览并导出，默认脱敏且不自动外传；平台健康信息与业务内容分开。私有部署必须能按声明的外部依赖独立安装、升级和恢复；SaaS 与私有版使用同一套核心功能验收，但可用性和隔离声明依实际拓扑/证据分别给出。
