# M0-02 契约与真实执行对账

2026-11-06。范围为客户端、控制面与 Runner 的调用约定。以 [M0-02 原任务](../docs/planning/BACKLOG.md)、[验收条件](../docs/planning/ACCEPTANCE.md)和[证据索引](../docs/planning/M0-RESULTS.md)判定。

| 场景 | 本轮固定的调用约定 | 已有证据及剩余验证 |
| --- | --- | --- |
| 提交超时或重放 | 以原会话和同键只读找已提交受理结果，必要时同键重发；摘要包含路径目标，重放前重新授权 | 已补机器路由；真实事务回滚、同键冲突和撤权按 M1-06/AC-28 |
| 流断线、游标过期 | 平台在提交时分配 Run seq；快照同取状态、当前待处理交互和游标。首次受理无需 Attempt，Runner 观察不能上报平台状态事件 | E44 显示原生流、历史和续聊各自独立；E59/E60 有本地 spool 恢复和容量停止证据；控制面连续提交、补取和历史恢复按 M1-06/M2-06/M3、AC-06/29 |
| 取消与未知执行 | 原生取消回执、平台取消受理、受信宿主停止分别处理。未知保留 reconciling；只有确认是同一次执行才可接回，分配新 Attempt 前先确认旧写者不存在并完成 fencing | E48/E60/E62/E67/E76 支撑固定资源核对、截止、容量停止和专用身份的限定结论；AC-30 的真实不确定派发及伪造 Guest 停止 ACK 仍需补证 |
| 审批过期或换代 | 服务端按当前授权、参数摘要、Attempt、租约、修订和服务端时钟原子判定；过期或被替换的动作拒绝 | E44 涵盖已验证组合的原生拒绝及限制；平台过期、撤权与并发决策按 M3-03/AC-10 |
| 组件不兼容与能力范围 | 桌面用用户 Access Token，Runner 用 mTLS；无版本交集以明确错误拒绝。能力关联不可变部署修订，变更配置或目标须重新核对 | E44 支撑 Hermes → OpenCode → OpenClaw 的固定组合顺序。Octop 服务、SDK、委派分别计证；DSH 仍为 preview。真实兼容拒绝和 Adapter 能力见 M1-06/M2-01/M4 |

本地 Python 3.12 与仓库 hash 锁下通过 64 定义、20 路径、128 正负样例及 15 迁移案例。E02/E77 为修订前证据；本轮按变更输入执行契约检查。验证覆盖结构与迁移表，实际事务、隔离、权限和资源归属沿用各阶段的真实验收。

**M0-02 保持 IMPLEMENTED。** 正式准入冻结依赖 M0-05。AC-12 需要在同一真实执行路径取得 Guest 选择性出网、未授权文件/记忆/凭据/评分器访问拒绝和适用配额证据。E30 的临时 NIC、E52 的宿主代理传输及 E76 的临时专用身份授权分别复用；三者不能合并为一次实际 Guest 授权链。下一项先对 AC-12 核对可复用的最小 Guest 路径及前置条件，AC-30 的未决项单列；完整控制面授权与持久运营归 M1/M2/M7。
